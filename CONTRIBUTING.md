# Внести вклад в TarkovStation

Контрибуции открыты: код, карты, интерфейсы, исправления, переводы и ресурсы. Крупную механику или изменение экономики сначала обсуди в [Discord](https://discord.gg/jgUJ9Kwa7K) или issue.

## Работа с кодом

1. Создай fork репозитория и отдельную ветку от `main`.
2. Ограничь PR одной задачей. Сохрани чужие изменения и исходное авторство.
3. Новый контент размещай в `_TarkovStation` внутри соответствующих Content-проектов и Resources.
4. Состояние храни в компонентах, логику в системах. Проверяй запросы игрока на сервере.
5. Для видимых строк добавляй одинаковые ключи и переменные в ru-RU и en-US.
6. Не добавляй в клиентские сборки API, запрещённые песочницей. Серверные операции, файловый доступ и внешние сервисы оставляй на сервере.

В C# используются четыре пробела, в YAML два. Текстовые файлы: UTF-8, LF и перевод строки в конце. Следуй `.editorconfig`. Изменения в унаследованных файлах отмечай комментарием `TarkovStation-Edit` с причиной.

При переносе кода из Reserve, Goob или другого форка адаптируй его к нашей версии движка и зависимостям. Сохраняй SPDX-заголовки, лицензии и атрибуции ресурсов. Указывай источник переноса в PR.

## Проверки

Проверяй затронутую часть. Для документации достаточно проверить ссылки и формат. Для C# нужна сборка. Для игровых изменений опиши, как проверил поведение.

```bash
dotnet build Content.IntegrationTests/Content.IntegrationTests.csproj -c Release
git diff --check
```

Клиентские и общие сборки обязательно проверяются штатной песочницей. Обычная успешная сборка не обнаруживает все запрещённые API.

```bash
dotnet test Content.IntegrationTests/Content.IntegrationTests.csproj -c Release --no-build \
  --filter FullyQualifiedName=Content.IntegrationTests.Tests.Utility.SandboxTest.Test
```

Для прототипов используется `Content.YAMLLinter`, для RSI `RobustToolbox/Schemas/validate_rsis.py`. Общие проверки исходного SS14 остаются в `Content.Tests` и `Content.IntegrationTests`. Отдельных Tarkov-интеграционных сценариев в репозитории нет.

Не используй рабочую серверную базу для экспериментов и не включай её в PR. Для локального запуска укажи отдельный `TARKOV_DATA_DIR`. Токены, ключи, логи игроков и содержимое обращений в репозиторий не отправляются.

## Pull request

Заполни [шаблон](.github/PULL_REQUEST_TEMPLATE.md): какую проблему решает изменение, что изменилось и как это проверено. Для интерфейса, карты или спрайтов приложи изображения. Для изменения механик опиши заметный игроку результат.

Отмечай только выполненные проверки. Если проверка недоступна, укажи причину. Не смешивай механики с обновлением движка или массовым форматированием.

Ревью проходит в PR. Замечания по игровой ситуации и жалобы на участников направляй в Discord.
